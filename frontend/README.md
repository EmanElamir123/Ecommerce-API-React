# دُكّان — فرونت إند React للمتجر الإلكتروني

فرونت إند منفصل بالكامل مبني بـ **React + Vite**، بيتكلم مع الباك إند (.NET) بتاعك عن طريق الـ REST API الموجود في `Ecommerce.Api`. الواجهة عربي بالكامل (RTL)، مبنية بـ **Bootstrap 5 (RTL)** و **Font Awesome** للأيقونات، مع ثيم ألوان وخطوط مخصص (خط Tajawal) عشان الشكل يبقى مميز.

---

## 1. التشغيل خطوة بخطوة

### أ) تجهيز الباك إند (خطوة مهمة جدًا — CORS)
الباك إند بيرفض أي طلب من دومين تاني لحد ما تضيفه في إعدادات الـ CORS. افتح ملف:

```
Ecommerce/src/Ecommerce.Api/appsettings.json
```

وعدّل السطر ده:

```json
"Cors": { "AllowedOrigins": [] }
```

يبقى:

```json
"Cors": { "AllowedOrigins": ["http://localhost:5173"] }
```

(`5173` هو بورت Vite الافتراضي). بعدين شغّل الباك إند عادي (`dotnet run` من `src/Ecommerce.Api`).

### ب) تجهيز الفرونت إند

```bash
cd frontend
npm install
cp .env.example .env
```

افتح `.env` وتأكد إن `VITE_API_BASE_URL` مطابق للعنوان اللي الباك إند شغال عليه (موجود افتراضيًا `http://localhost:5289/api` حسب `launchSettings.json`).

```bash
npm run dev
```

المشروع هيفتح على `http://localhost:5173`.

## 2. هيكل المشروع

```
frontend/
├─ src/
│  ├─ api/                  # كل طلبات الـ API متقسمة حسب الموضوع (auth, products, catalog, orders, users)
│  ├─ context/               # AuthContext (تسجيل الدخول) + CartContext (سلة التسوق)
│  ├─ components/
│  │  ├─ layout/             # Navbar, Footer, Layout
│  │  ├─ common/             # مكونات عامة: Spinner, Pagination, EmptyState, حراسة الصفحات (Protected/AdminRoute)
│  │  ├─ products/            # بطاقة المنتج، الفلاتر، الشبكة
│  │  ├─ cart/                # عناصر السلة والملخص
│  │  ├─ orders/               # بطاقة الطلب وشارة الحالة
│  │  └─ admin/                # مكونات لوحة التحكم (زي CatalogManager القابل لإعادة الاستخدام)
│  ├─ pages/                  # كل صفحة مستقلة (Home, ProductsPage, CartPage, CheckoutPage...)
│  │  └─ admin/                # صفحات لوحة التحكم (Dashboard, Products, Categories, Brands, Featured, Users)
│  ├─ utils/
│  │  ├─ formatters.js        # تنسيق السعر، التاريخ، ألوان حالة الطلب
│  │  └─ lookups.js           # ⚠️ قيم ثابتة مهمة (اقرأ القسم الجاي)
│  ├─ styles/theme.css        # الثيم البصري المخصص فوق Bootstrap
│  ├─ App.jsx                 # كل الـ Routes
│  └─ main.jsx                # نقطة الدخول + تحميل الـ CSS/JS
```

كل ملف له مسؤولية واحدة بس، عشان لو حبيت تضيف صفحة أو تعدّل حاجة تلاقيها بسهولة من غير ما تدوّر في كل المشروع.

## 3. ⚠️ ملاحظة مهمة: `src/utils/lookups.js`

الـ API الحالي **مبيوفرش endpoints** لجلب:
- أنواع الدفع (`PaymentTypeId`)
- طرق الشحن (`DistributionChannelId`)
- المحافظات (`ProvinceId`)

القيم دي أرقام IDs متعرّفة بس جوه قاعدة البيانات. عشان صفحة الـ Checkout تشتغل، حطينا قيم افتراضية منطقية في `src/utils/lookups.js` مع تعليق واضح فوق كل واحدة.

**لازم تتأكد إن الأرقام دي مطابقة فعلاً لقاعدة بياناتك**، ولو مختلفة عدّلها في الملف ده بس (مكان واحد مركزي). أفضل حل نهائي: إضافة endpoint بسيط زي `GET /api/lookups` في الباك إند يرجّع القوائم دي جاهزة من الداتابيز.

أما الأدوار (Roles) فمتطابقة فعلًا مع `Ecommerce.Domain.Enums.LegacyRoles` في الباك إند، فمش محتاجة تعديل.

## 4. المميزات المتوفرة

**للعميل:**
- تصفح المنتجات بالفلاتر (تصنيف، ماركة، توفر، ترتيب) + بحث
- صفحة تفاصيل منتج مع معرض صور
- سلة تسوق (متخزنة في المتصفح)
- إتمام الشراء كضيف أو كعضو مسجل
- تسجيل دخول / إنشاء حساب
- طلباتي + تفاصيل كل طلب
- تتبع الطلب كضيف (برقم الطلب وكود التتبع)
- الملف الشخصي وتغيير كلمة المرور

**للإدارة (Admin):**
- لوحة تحكم بإحصائيات (طلبات مكتملة، منتجات نشطة، الأكثر مبيعًا/زيارة)
- إدارة المنتجات (إضافة/تعديل/تعطيل) مع صور وتصنيفات وماركات
- إدارة التصنيفات والماركات
- إدارة المنتجات المميزة (Featured)
- إدارة المستخدمين والصلاحيات
- البحث عن طلب وتقديمه للحالة الجاية

## 5. تشغيل نسخة الإنتاج (Build)

```bash
npm run build
npm run preview
```

الملفات الجاهزة هتلاقيها في `dist/` وممكن ترفعها على أي استضافة استاتيك (Vercel, Netlify, IIS...) بس لازم تحدّث `VITE_API_BASE_URL` بعنوان الباك إند الحقيقي وقتها.
